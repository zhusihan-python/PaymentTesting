Module 4：EMV 与 PCI-DSS 安全合规测试

在支付测试中，功能跑通只是及格线；守住“密钥验签”与“敏感数据不落盘”才是专业底线。

1. PCI-DSS 两类核心数据边界（必背）

数据分类包含字段存储要求展示与日志要求
CHD（持卡人数据） 主账号（PAN）、持卡人姓名、有效期、服务代码 允许存储，但 PAN 必须强加密（AES-256）或令牌化（Tokenization） 必须掩码脱敏（最多仅展示前 6 后 4 位，如 411111******1111）
SAD（敏感验证数据） CVV/CVC 安全码、PIN / PIN Block、完整磁道数据 严禁以任何形式落盘存储（授权完成后必须立刻从内存销毁，哪怕加密也不行） 严禁打印到任何日志（应用日志、网关日志、ELK、监控链路）
PCI-DSS 测试铁律：在 CI/CD 回归测试结束后，必须自动扫描测试环境日志与数据库。只要发现一条未脱敏的明文卡号（PAN）或任意落盘的 CVV/PIN，直接判定为 P0 级阻断缺陷。

2. EMV 与 HSM 加密机测试要点

ARQC / ARPC 动态验签芯片生成一次性密文 ARQC 随 F55 上送，发卡行通过 HSM 校验通过后返回 ARPC。测试需覆盖篡改金额导致验签失败（F39=05）。
PIN Block 加密与锁卡用户密码绝不以明文传输，而是封装为加密 PIN Block。测试需验证连续 3 次错误 PIN 触发自动锁卡（F39=75）。
密钥轮换（Key Rotation）定期更换工作密钥（ZPK/PEK）时，验证新旧密钥平滑切换，不出现大面积交易验签失败。
