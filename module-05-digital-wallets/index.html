Module 5：数字钱包与令牌化（Tokenization）

用户把卡绑进 Apple Pay / Google Pay 时，手机里存的从来不是真实卡号，而是卡组织颁发的“替身令牌”。

1. FPAN（真实主卡号） vs DPAN（设备令牌）

维度FPAN (Funding PAN)DPAN (Device PAN / Token)
本质发卡行颁发的真实 16 位银行卡号由卡组织令牌服务（Visa VTS / MC MDES）生成的虚拟替身卡号
存储位置发卡行核心系统、实体卡片手机安全芯片（Secure Element / SE）或云端钱包
对应关系1 张主卡（FPAN）可对应 N 个不同设备的 DPAN（iPhone、Apple Watch、iPad 各一个）
交易过程发卡行最终在主卡账务扣款POS 收到的是 DPAN → 卡组织内部映射还原为 FPAN → 转发给发卡行

2. 绑卡身份核验（ID&V）三条风控路由

🟢 绿通（Green Path）低风险（如 App 内一键推送绑卡，已登录验密），直接激活 DPAN，无需二次验证。
🟡 黄通（Yellow Path）中风险（如手动输入卡号绑卡），下发短信 OTP / 邮箱验证码 / 客服核身，通过后激活。
🔴 红通（Red Path）高风险（如设备越狱、黑名单、卡已冻结），发卡行直接拒绝绑卡请求。
