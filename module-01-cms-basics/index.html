Module 1：支付基石与卡管理系统（CMS）状态机

80% 的发卡行资损 Bug，都源于对“两阶段资金流”和“卡状态机边界”的理解偏差。

1. 联机授权（Authorization） vs 批处理清算（Clearing）

维度阶段一：联机授权（Authorization）阶段二：批处理清算（Clearing）
发生时间实时（毫秒至秒级）T+1 至 T+N（隔日凌晨批处理）
通信载体联机实时报文（ISO 8583 0100/0110）批量清算文件（Visa BASE II / MC IPM）
资金动作仅冻结额度（可用减少，冻结增加）实际扣款核销（释放冻结，真实划拨）
测试重点余额校验、风控拦截、超时冲正小费/汇率差额、长短款对账、重复清算幂等
防资损基石：账务系统里用户的钱分为两个桶——可用余额（Available）和冻结金额（Frozen）。授权只把钱从“可用”挪到“冻结”；只有收到清算文件，钱才真正离开账户。

2. CMS 卡生命周期状态机

Inactive（未激活）卡号已生成，不可消费，通常不可绑钱包。
Active（正常）允许消费授权、绑卡、调额。
Frozen（临时冻结）可逆。拦截新授权，但需放行在途清算与退款。
Lost / Stolen（挂失）不可逆，通常触发换卡（Reissue）。
Closed（已销卡）终态。销卡前必须校验在途冻结资金。
